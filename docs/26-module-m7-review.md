## 2. Pre-Implementation Architecture Review

Per the brief's explicit process gate, the plan went through two rounds:

1. **Initial architecture plan** — `ThemeProvider` abstraction, `packages/themes` structure, the AI-recommends/rules-validate selection flow, the 16-field output contract, versioning strategy, and API surface — presented with two explicit open forks flagged: brand-field sourcing (do colorPalette/typography/layoutStyle pass through from M6 or get regenerated per-theme?) and permission naming (`theme:select` vs. reusing `business:analyze`).
2. **Founder follow-up**, resolving both forks explicitly and adding requirements beyond the original brief: the brand-identity lock extended to 9 named fields (not just the 3 the architecture doc's fork covered), a dedicated `theme:select` permission, four additional required output fields, an explicit compatibility-validation gate with `THEME_NOT_FOUND`, and — delivered in a second message — the full-ranking requirement replacing the original single-recommendation design.

Full reasoning: `DECISIONS.md` D-044 through D-047.

One design judgment made without being asked, flagged rather than silently decided: `POST /leads/:id/theme` runs synchronously (`201`/`200`, no `PENDING` state), unlike M6's fire-and-forget `202` pattern — justified by the AI step being a single lightweight call rather than a potentially-3-attempt escalation ladder.

**Follow-up (2026-07-31):** after this review's initial pass flagged the missing `CostService` integration as a known limitation (§7, original version), the founder required it closed out as a final, tightly-scoped M7 improvement before M8 begins: reserve estimated cost before the AI request, record actual usage/cost/provider/model/duration after, respect the monthly ceiling, reuse `CostService` as-is, duplicate no cost-tracking logic, change no other behavior. Full reasoning: DECISIONS.md D-048.

## 3. Implementation Summary

**`packages/themes`** (new package, mirrors `packages/ai`'s structure/build step): `provider/theme-provider.interface.ts` (`ThemeProvider`, `THEME_PROVIDER`, `ThemeDefinition`), `provider/static-theme-registry.ts` (`StaticThemeRegistry`), `provider/theme-hash.ts` (`computeThemeHash`), `definitions/*.theme.ts` (8 modules), `scoring/compatibility-scorer.ts` (`scoreThemeCompatibility`, `rankThemes`, `MINIMUM_COMPATIBILITY_SCORE`).

**`packages/ai` extension:** `prompt/theme-recommendation/v1.0.ts` (new versioned template), `PromptRegistry.resolveThemeRecommendation()`, `validator/theme-recommendation-validator.ts`, `AiService.recommendThemeCategory()` — additive only, M6's `analyzeBusiness()` untouched.

**Schema (`packages/db/prisma/schema.prisma`, migration `20260730030000_m7_theme_engine`):** 7 new enums (NavigationStyle, HeroStyle, CtaStyle, CardStyle, FooterStyle, AnimationLevel, ImageStyle), new `ThemeConfiguration` model, relations added to `Business`/`BusinessAnalysis`. Purely additive — no existing table altered.

**Contracts (`packages/shared-types/src/theme-configuration.ts`):** `themeConfigurationSchema`, `rankedThemeEntrySchema`, `accessibilityProfileSchema`, `mobilePreferencesSchema`, `THEME_CATEGORIES` and the 7 style enums.

**Services (`apps/api/src/theme-engine/`, `apps/api/src/common/theme/`):** `ThemeModule` (DI wiring for `THEME_PROVIDER`), `ThemeSelectionService` (cache check by `businessAnalysisId`, AI-recommends step, rule-based ranking, versioned persistence), `ThemeSelectionController` (`GET/POST /leads/:id/theme`), `theme-style.mapper.ts` (Prisma ⟷ API enum conversion), `dto/theme-configuration-response.dto.ts`.

**Logging:** `Logger` on `ThemeSelectionService`, matching every prior module's convention — cache hit/miss, AI recommendation received/failed, no-compatible-theme warning, completion.

**CostService follow-up (D-048):** `ThemeSelectionService` now injects the existing `CostService` (unchanged) and calls `charge('theme_ai_recommendation', AI_THEME_RECOMMENDATION_ESTIMATED_COST_USD, {businessId})` as the first statement inside the existing AI try/catch, immediately before `recommendThemeCategory()` — a `QuotaExceededException` is caught by that same handler, not a new one. New shared `apps/api/src/common/cost/ai-cost.util.ts` (`computeActualAiCostUsd`) holds the token→USD formula previously private to `BusinessAnalysisRunnerService`; both M6 and M7 now call it. New `AI_THEME_RECOMMENDATION_ESTIMATED_COST_USD` ($0.02) constant in `cost.constants.ts`. Schema: 7 new nullable columns on `ThemeConfiguration` (`aiRecommendationProvider`/`Model`/`PromptTokens`/`CompletionTokens`/`TotalTokens`/`CostUsd`/`ExecutionTimeMs`), folded into the still-unshipped `20260730030000_m7_theme_engine` migration rather than a second migration (D-048's migration-amendment rationale).

## 6. Security Review

- **AuthZ** — `POST /leads/:id/theme` requires the new `theme:select` permission (same role set as `business:analyze`); `GET` requires only `leads:read`. Verified: a Viewer gets 403 on POST, 200 on GET.
- **Cost governance (closed out by the D-048 follow-up)** — the AI recommendation step now reserves `AI_THEME_RECOMMENDATION_ESTIMATED_COST_USD` against the org-wide monthly ceiling via `CostService.charge()` before every `recommendThemeCategory()` call, and durably logs a `cost_event` row on acceptance, exactly like M6's `analyzeBusiness()`. A ceiling-exceeded rejection degrades to rules-only selection rather than failing the request — verified by e2e test.
- **No secrets/PII newly logged** — log lines carry businessId/themeId/scores only.

## 7. Known Limitations (flagged, not hidden)

- The migration has not been run against a real Postgres instance — same constraint as every prior module.
- Compatibility-score weighting (industry 40% / layout 20% / accessibility 15% / mobile 10% / component availability 15%) is a considered but ultimately judgment-call starting point — no real selection data exists yet to validate it against.
- `packages/themes`' 8 theme definitions are hand-authored, reasonable-but-illustrative content (not derived from real design research) — flagged as a starting point for founder/design review, not a claim of production-grade visual design decisions.
- **Resolved since the original review:** the missing `CostService` integration flagged in the original (2026-07-30) version of this section was closed out by the 2026-07-31 founder-directed follow-up (DECISIONS.md D-048) — see §2's follow-up note and §6.
