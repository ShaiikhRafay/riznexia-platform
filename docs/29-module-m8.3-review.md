## 2. Pre-Implementation Architecture Review

The founder's phase brief specified the objective, inputs/outputs, the no-AI/deterministic-mapping requirement, the validation list, and the SEO/structured-data requirements directly, followed by an explicit "every field traceable to its origin" requirement with a concrete `{value, source}` example. Before any code was written, an architecture was presented covering the full `ContentManifest`/`SourcedValue` TypeScript shape and the deterministic binding rules per field — with three open forks flagged explicitly:

1. **Missing-source required content** — several component types (FAQ, class schedules, pricing plans, client logos, team profiles) have a required slot with no real upstream data anywhere. Three options were presented (explicit gap list, manifest still validates; hard-fail for any theme with an unsourceable required component; silently omit with no flag). Founder chose the first — DECISIONS.md D-061.
2. **Testimonials source** — bind from `socialProofSuggestions`/`trustSignals` (honestly labeled as AI-suggested angles) vs. treat as unsourced like FAQ. Founder chose to bind, honestly labeled — DECISIONS.md D-063.
3. **SEO meta title/description composition** — fixed-template assembly from real fields vs. leave unresolved. Founder chose template assembly (which, on reflection, only `metaTitle` needed — `metaDescription` maps `businessSummary` verbatim with no template at all) — DECISIONS.md D-064.

Two additional gaps were found during design and resolved without a fourth AskUserQuestion round, since neither had a real competing alternative:

- **`Business` as a necessary 5th input** — Contact Information/Business Hours/Gallery References/`LocalBusiness` structured data are impossible to bind without raw `Business` fields, which live outside all four of the brief's stated inputs. Added as a minimal `BusinessContactInfo` shape — DECISIONS.md D-062.
- **Real Google review text in `Business.placesData.fullDetails.reviews` deliberately not used** — a stronger testimonials source than `socialProofSuggestions`, but its shape isn't a stable typed contract anywhere in this codebase. Flagged as a known limitation (§7) rather than silently implemented — DECISIONS.md D-062.

Full reasoning: `DECISIONS.md` D-061 through D-067.

**Design note carried forward without re-asking:** validation-failure semantics (internal assertion vs. new domain exception) were already resolved for this same package/module in M8.1/M8.2 (D-052/D-060); the identical reasoning was carried forward rather than re-litigated — DECISIONS.md D-067.

## 3. Implementation Summary

**Contracts (`packages/shared-types/src/content-manifest.ts`):** five "sourced value" schemas (`sourcedTextSchema`, `sourcedTextListSchema`, `sourcedLinkSchema`, `sourcedLinkListSchema`, `sourcedImageRefSchema`), `contentFieldBindingSchema`, `unresolvedBindingSchema`, `seoMetadataSchema`, `structuredDataBindingSchema`, `contentManifestSchema`, and the new `BusinessContactInfo` interface (D-062).

**New `packages/website-generator/src/content/`** (extends the D-050 package): `content-binding-rules.ts` (`bindComponentContent()`, one resolver per (componentType, slotName) pair, `titleCase()`), `seo-binder.ts` (`bindSeoMetadata()`, `bindStructuredData()`), `content-generator.ts` (`generateContentManifest()`, `CONTENT_ENGINE_VERSION`), `content-validator.ts` (`validateContentManifest()`), `content-fixtures.ts` (shared test fixtures reusing the real `generateLayout()`/`generateComponentManifest()`).

**Schema (`packages/db/prisma/schema.prisma`):** new `ContentManifest` model — versioned, quad-FK (`businessAnalysisId`, `themeConfigurationId`, `layoutConfigurationId`, `componentManifestId`), all four compound fields as `Json`. New, purely additive migration `20260802000000_m8_3_content_binding`.

**Services (`apps/api/src/content-engine/`):** `ContentEngineModule` (imports `BusinessModule` for the raw `Business` record, `LeadsModule`), `ContentBindingService` (cache check by `componentManifestId`, bind + validate + versioned persistence), `ContentBindingController` (`GET/POST /leads/:id/content`), `dto/content-manifest-response.dto.ts`, `dto/business-contact-info.mapper.ts`.

**Exceptions/permissions:** new `ComponentManifestNotFoundException` (`COMPONENT_MANIFEST_NOT_FOUND`, 404); new `content:bind` permission, same role set as `component:generate`/`layout:generate`/`theme:select`.

**Logging:** `Logger` on `ContentBindingService` — cache hit/miss, completion with bound-field and unresolved counts.

## 6. Security Review

- **AuthZ** — `POST /leads/:id/content` requires the new `content:bind` permission (same role set as `component:generate`/`layout:generate`/`theme:select`); `GET` requires only `leads:read`. Verified: a Viewer gets 403 on POST, 200 on GET.
- **Cost governance** — not applicable. `generateContentManifest()` calls no external service (no AI, no third-party API) — same as M8.1/M8.2, nothing to meter against the monthly cost ceiling.
- **No secrets/PII newly logged** — log lines carry businessId/componentManifestId/bound-and-unresolved counts only. `Business.phone`/`.address` are bound into the manifest itself (expected, since Contact Information is an explicit output requirement) but never appear in log lines.

## 7. Known Limitations (flagged, not hidden)

- The migration has not been run against a real Postgres instance — same constraint as every prior module.
- **Real Google review text (`Business.placesData.fullDetails.reviews`) is not used for testimonials this phase** (D-062) — `socialProofSuggestions` (AI-suggested angles) is the sole testimonials source. `placesData`'s shape isn't a stable typed contract anywhere in this codebase (it varies by which sync path wrote it), so reaching into it from a pure typed binder was judged the wrong tradeoff. A future refinement could add a typed `placesData` accessor and prefer real review text when present.
- FAQ, class schedules, pricing plans, client logos, and individual team-member profiles have **no upstream data source anywhere in the pipeline** — these are recorded in `unresolvedBindings` for every theme that includes such a component (5 of 8 themes). This is a real product gap, not an M8.3 implementation gap: closing it requires new data collection (e.g. a founder-authored FAQ field, a pricing-plan input) upstream of M6, out of scope for Content Binding itself.
- `metaTitle`'s template (`"${businessName} | ${industry} in ${city}"`) is a single fixed format — no per-industry or per-theme variation. A reasonable v1 starting point per the "fixed, non-creative template" resolution, not a claim of SEO-optimized copywriting.
- `BreadcrumbList` reflects this pipeline's own section navigation (Home + each section), not a real multi-page URL hierarchy — appropriate for a single-page generated site today, but will need revisiting if M9/M11 introduce true multi-page sites.
