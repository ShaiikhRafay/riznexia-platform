### M8.1 — Layout Generator (phase 1 of 4 for Module M8 — Website Generator)

- **Added:** `sectionComponentMap` on `ThemeDefinitionContent` (`packages/themes`) — an explicit `{sectionId: componentId[]}` binding, closing a real gap in M7's data model (`componentSet`/`sectionOrder` were two independent flat lists with no link between them). Populated for all 8 existing theme definitions; a new registry invariant test asserts every `componentSet` entry is mapped exactly once, keyed only by real sections. Copied through onto `ThemeConfiguration` (new column, amended into the still-unshipped M7 migration).
- **Added:** New `packages/website-generator` package (Module M8's package — one per module, one subdirectory per phase, mirroring `packages/ai`'s internal structure rather than four near-empty packages). `layout/layout-generator.ts`: `generateLayout(brandBrief, themeConfiguration)` — pure and deterministic (fixed lookup tables + arithmetic only; no AI call, no `Date.now()`/`Math.random()`, no I/O), producing page structure, navigation/hero/footer/sidebar layout, grid definitions, responsive rules, CTA placements, and component placeholders. Structure only — no HTML, no React, no display copy, no images, per the phase brief's explicit exclusions.
- **Added:** `layout/layout-validator.ts`: `validateLayoutConfiguration()` — checks required sections exist, responsive rules exist, accessibility constraints, navigation integrity, and section ordering. Throws a plain internal error (never a new domain exception/HTTP code) on failure — since every input is already M6/M7-validated and every rule is a fixed lookup, a failure here means a generator bug, not a legitimate business outcome (a different failure model than M7's `THEME_NOT_FOUND`).
- **Added:** New `LayoutConfiguration` schema (`packages/shared-types/src/layout-configuration.ts`) and Prisma model — versioned per business like `BusinessAnalysis`/`ThemeConfiguration` (never overwritten), FK'd to both `businessAnalysisId` and `themeConfigurationId` for full provenance. New, purely additive migration.
- **Added:** `layout-engine` module (`apps/api`) — `GET/POST /leads/:id/layout`, gated by a new dedicated `layout:generate` permission (same role set as `theme:select`/`business:analyze`), cached per `themeConfigurationId`. New `ThemeConfigurationNotFoundException` (`THEME_CONFIGURATION_NOT_FOUND`, 404) for the hard dependency on a persisted M7 `ThemeConfiguration`.
- **Docs:** The phase brief (objective, inputs/outputs, determinism requirement, validation list) was given up front; architecture (package placement, `LayoutConfiguration` shape, derivation rules) was then presented with three open forks — the component↔section mapping gap, validation-failure semantics, and whether to ship an API endpoint this phase — all resolved before implementation. See DECISIONS.md D-049, D-050+.
- **Tests:** 28 new `packages/website-generator` tests (new package: 18 generator incl. a determinism assertion, 10 validator); 12 new `apps/api` unit tests (347 total, up from 335); 1 new `packages/themes` invariant test (18 total, up from 17); 13 new `packages/shared-types` tests (102 total, up from 89). New `apps/api/test/layout.e2e-spec.ts`, 12 tests including the full real (unmocked) generation flow (118 e2e total, up from 106).

### M7 — Theme Engine

- **Added:** New `packages/themes` package — `ThemeProvider` interface + `THEME_PROVIDER` DI token (registry-shaped: every registered theme is simultaneously available, unlike M5/M6's single-active-implementation provider abstractions); `StaticThemeRegistry` the sole implementation; 8 named theme definition modules (Restaurant, Salon, Dental, Law Firm, Gym, Real Estate, Medical, Corporate), each a versioned code module carrying name/version/hash/createdAt/updatedAt (hash computed from content at load, same technique as M6's `PROMPT_HASH`).
- **Added:** Deterministic compatibility scorer (`packages/themes/src/scoring/`) — 5 weighted checks (industry, layout, accessibility, mobile, component availability) per theme; `rankThemes()` scores every registered theme and returns only those clearing the minimum compatibility score, sorted descending. An empty result is the founder's explicit contract: `THEME_NOT_FOUND`, never a forced bad fit.
- **Added:** `AiService.recommendThemeCategory()` (`packages/ai`) — the "AI recommends" half of "AI recommends, rules validate." A single lightweight classification call (new `theme-recommendation/v1.0` prompt template), transient-retried only, no repair-prompt ladder or model escalation. Never throws — any failure resolves to a typed `failed` outcome so rule-based ranking always has a working zero-AI-dependency fallback path.
- **Added:** `BusinessAnalysis.brandBrief`'s `colorPalette`/`typography`/`layoutStyle`/`industry` flow through into `ThemeConfiguration` verbatim — theme selection never regenerates or overrides brand-identity fields M6 already produced. Only structural/presentational fields (component set, navigation/hero/CTA/card/footer style, animation level, image style, section order, accessibility profile, mobile preferences) come from the selected theme.
- **Added:** `ThemeConfiguration` schema — versioned per business like `BusinessAnalysis` (never overwritten), FK'd to the exact `businessAnalysisId` it was derived from, full theme-versioning provenance (`themeName`/`themeVersion`/`themeHash`/`selectedAt`/`selectedByEngineVersion`/`compatibilityScore`), and the complete ranked-theme list stored as JSON for a future manual-override feature. 7 new Prisma enums for the structural fields.
- **Added:** `theme-engine` module — `GET/POST /leads/:id/theme`, gated by a new dedicated `theme:select` permission (not a reuse of `business:analyze` — theme selection is its own independent, cost-bearing capability with its own future extensions: premium themes, a theme marketplace, manual override, an approval workflow, agency-specific themes). Runs synchronously (unlike M6's fire-and-forget dispatch) and is cached per `businessAnalysisId`.
- **Added (post-review follow-up):** `ThemeSelectionService` now integrates with M6's `CostService` — reserves `AI_THEME_RECOMMENDATION_ESTIMATED_COST_USD` ($0.02) against the monthly ceiling immediately before calling `recommendThemeCategory()`, and on success persists actual `aiRecommendationProvider`/`aiRecommendationModel`/`aiRecommendationPromptTokens`/`aiRecommendationCompletionTokens`/`aiRecommendationTotalTokens`/`aiRecommendationCostUsd`/`aiRecommendationExecutionTimeMs` onto the `ThemeConfiguration` row (7 new nullable columns, folded into the not-yet-shipped M7 migration). A ceiling-exceeded rejection is handled by the exact same resilience path as any other AI failure (D-046) — theme selection still succeeds, rules-only, and the new fields stay `null`. The cost-computation formula was extracted out of `BusinessAnalysisRunnerService` into a new shared `apps/api/src/common/cost/ai-cost.util.ts` so M6 and M7 call the same function rather than each carrying their own copy. See DECISIONS.md D-048.
- **Docs:** The architecture was presented and approved in two rounds — an initial ThemeProvider/rule-based-selection design, then a founder follow-up locking the brand-field sourcing, the permission choice, four additional required `ThemeConfiguration` fields, the compatibility-validation gate, and the full-ranking requirement. See DECISIONS.md D-044 through D-047.
- **Tests:** 24 new `apps/api` unit tests + 1 permission-matrix assertion, plus 4 more from the CostService follow-up (335 total, up from 307); 11 new `packages/ai` tests (30 total, up from 19); 17 new `packages/themes` tests (new package); 13 new `packages/shared-types` tests, incl. 2 from the follow-up (89 total, up from 76). `apps/api/test/theme.e2e-spec.ts`, 13 tests including the full AI-recommends+rules-rank flow (run against the real, unmocked theme registry and scorer) and the cost-ceiling-reached resilience path added by the follow-up (106 e2e total, up from 93).
- **Not built, deliberately:** HTML generation, React components, complete websites, frontend, manual theme override — only a validated `ThemeConfiguration` is produced, per explicit instruction.

- **Added:** `ResponseValidator` (Zod, `businessAnalysisOutputSchema` from `packages/shared-types`) — never throws, strips a stray markdown code fence, returns a discriminated validation result.
- **Added:** `AiService` gateway — the full retry/escalation ladder (initial attempt → 1x same-model repair-prompt retry → 1x escalation to a stronger model → `FAILED`), each attempt wrapped in `withExponentialBackoff` for transient failures (kept strictly separate from the validation-repair ladder), with structured event emission for logging.
- **Added:** `BusinessAnalysis` schema expanded from two opaque `Json` columns to typed columns — `analysisVersion` (unique per business, historical rows never overwritten), `promptName`/`promptVersion`/`promptHash`, `aiProvider`/`aiModel`, `inputHash` (AI result cache key), `status`, `confidenceScore`, `rawResponse`/`validationErrors` (FAILED only), token/cost/timing fields. - **Added:** `business-analysis` module — `GET/POST /leads/:id/business` (Doc 19). New `business:analyze` permission (not a reuse of `leads:write` — it gates real AI spend, same rationale as `discovery:run` gating Places API spend), granted to the same role set. Fire-and-forget dispatch (D-004 precedent). Cost tracked as a conservative pre-flight reservation via `CostService.charge()`, with the real per-analysis cost (computed from actual token counts) persisted on the row.

#### Pre-close engineering audit (architecture/SOLID/performance/security/error-handling/logging/validation/scalability/test-coverage)

- **Fixed:** Cost-quota enforcement had a check-then-act race under concurrency — `CostService` now exposes one atomic `charge()` (reserve-first via Redis `INCRBY`, refunds on rejection) instead of separate check-then-spend calls (DECISIONS.md D-010).
- **Fixed:** Multi-category discovery-job creation wasn't transactional — a partial failure could orphan already-created rows. Now wrapped in `prisma.$transaction([...])` (D-011).
